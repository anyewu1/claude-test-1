# 校园助手 - 开发说明

> 项目开发笔记,记录架构设计、技术细节与开发心得。

## 一、项目架构

### 1.1 整体架构

```
┌─────────────────────────────────────┐
│         WeChat Mini-Program         │
├─────────────────────────────────────┤
│              View Layer             │  ← WXML + WXSS
│   (10 Pages + Reusable Components)  │
├─────────────────────────────────────┤
│             Logic Layer             │  ← Page.js (JavaScript)
│  (Event Handler, Lifecycle, State)  │
├─────────────────────────────────────┤
│              Data Layer             │  ← utils/storage.js
│    (wx.storage Local Persistence)   │
└─────────────────────────────────────┘
```

### 1.2 数据流

```
Mock Data (mock-data.js)
        │
        ▼ (App.onLaunch 时首次注入)
wx.storage (本地持久化)
        │
        ▼ (各页面 onLoad/onShow 读取)
Page.data (页面级状态)
        │
        ▼ (this.setData)
WXML View (UI 渲染)
        │
        ▼ (用户交互 bindtap 等)
Page Handler (业务逻辑)
        │
        ▼ (storage.set 写回)
wx.storage (持久化)
```

### 1.3 模块划分

| 模块 | 路径 | 职责 |
|------|------|------|
| 入口 | `app.js` | 全局数据、初始化 |
| 配置 | `app.json` | 路由、tabBar |
| 全局样式 | `app.wxss` | 主题色、通用组件样式 |
| 页面 | `pages/*` | 业务页面 |
| 工具 | `utils/*` | 通用函数封装 |
| 资源 | `images/*` | 静态图片资源 |

## 二、技术细节

### 2.1 路由设计

#### 4 个 tabBar 页面 (`wx.switchTab`)
- 首页 / 课表 / 通知 / 我的

#### 6 个普通页面 (`wx.navigateTo`)
- 成绩、图书馆、图书详情、日程、签到、设置

#### 跳转规则
- tabBar 页面之间互相跳转: `wx.switchTab`
- 普通页面跳转: `wx.navigateTo` (返回有动画)
- 图书详情等带参数页面: `wx.navigateTo({ url: '/pages/x/x?id=123' })`
- 重置数据后回到首页: `wx.reLaunch`

### 2.2 数据持久化

封装统一的 `storage` 模块:

```javascript
// utils/storage.js
module.exports = {
  get(key, defaultValue) { /* ... */ },
  set(key, value) { /* ... */ },
  remove(key) { /* ... */ },
  clear() { /* ... */ }
};
```

#### 优势
- 集中处理异常 (try/catch)
- 统一默认值逻辑
- 便于后续替换为云存储

### 2.3 状态管理

由于项目较小,未引入复杂的状态管理库。状态分布:

| 范围 | 存储 | 示例 |
|------|------|------|
| App 级 | `getApp().globalData` | studentInfo (常驻) |
| 页面级 | `this.data` | 当前筛选条件 |
| 持久化 | `wx.storage` | 业务数据 (notes, books) |

#### 跨页面数据同步
- 通过 `onShow` 在每次回到页面时重新读取 storage
- 避免使用全局事件总线,降低复杂度

### 2.6 关键算法

#### GPA 计算
```javascript
calcGPA(grades) {
  let total = 0, credits = 0;
  grades.forEach(g => {
    total += scoreToPoint(g.score) * g.credit;
    credits += g.credit;
  });
  return credits === 0 ? 0 : (total / credits).toFixed(2);
}
```

#### 成绩转绩点 (4 分制)
```javascript
90+ → 4.0   85+ → 3.7   82+ → 3.3
78+ → 3.0   75+ → 2.7   72+ → 2.3
68+ → 2.0   64+ → 1.5   60+ → 1.0
<60 → 0
```

#### 连续签到计算
从今天往前逐日检查,直到遇到未签到的日期为止。注意特殊情况: 今天未签到时,从昨天开始计算。

#### 月历构建
1. 计算当月第一天是星期几 (作为前置补空数量)
2. 渲染当月所有天
3. 后置补空到 42 格 (6 行 × 7 列)

## 三、开发难点与解决

### 难点 1: WXML 不支持函数调用
**问题**: 想在模板里写 `getCourses(day, period)` 不行
**解决**: 在 `Page.data` 预先构造好二维网格数据,模板只做遍历

### 难点 2: tabBar 必须使用 PNG
**问题**: 项目中没有 PNG 资源
**解决**: 用 Python 通过 zlib + struct 构造最小 81×81 纯色 PNG,满足编译要求,生产环境替换为真实图标

### 难点 3: 数据同步
**问题**: A 页面修改了 storage,B 页面未刷新
**解决**: B 页面在 `onShow` 中重新 `loadData()`

### 难点 4: WXSS 不能用 :hover
**问题**: 鼠标交互在小程序无意义
**解决**: 使用 `hover-class` 属性 + 主动样式 `.active`

### 难点 5: 弹窗调用 async/await
**问题**: `wx.showModal` 是回调式
**解决**: 在 `util.js` 中封装 Promise 版 `confirm()`

```javascript
confirm(content, title = '提示') {
  return new Promise(resolve => {
    wx.showModal({ title, content, success: r => resolve(r.confirm) });
  });
}
```

## 四、性能优化

1. **避免频繁 setData**: 多个状态变化合并为一次 `this.setData`
2. **避免大数据 setData**: 列表分页加载
3. **图片资源**: 使用 SVG / Emoji 替代位图
4. **样式优化**: 避免深层选择器,优先使用类名
5. **逻辑分离**: 复杂计算放 `onLoad`,渲染放 `setData`
